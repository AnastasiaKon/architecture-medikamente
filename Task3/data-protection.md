# Task 3. Data Encryption at Rest and In Transit

## 1. Классификация данных

Параметры классификации: категория по закону, чувствительность (уровень
C1-C4), состояние (at rest / in transit / in use), профиль риска (последствия
утечки для субъекта и компании), срок хранения.

| Уровень | Название | Примеры | Последствия утечки |
|---|---|---|---|
| C4 | Специальная категория ПДн, врачебная тайна | диагнозы, анамнез, заключения, результаты анализов, хронические заболевания | вред здоровью и репутации субъекта; ст. 13.11 КоАП, уголовная ответственность (ст. 137 УК); потеря доверия клиентов |
| C3 | ПДн прямой идентификации и финансовые | Ф. И. О. + дата рождения, паспорт, адрес, место работы, данные договора, платёжные данные, ИНН/СНИЛС сотрудников, зарплата | мошенничество, штрафы РКН, требования 152-ФЗ и ПЦИ DSS |
| C2 | Контактные и служебные ПДн | телефон, e-mail, `patient_id`, записи на приём (время, врач), логи с псевдонимами | спам, социальная инженерия; связывание с C3/C4 повышает риск |
| C1 | Внутренние нечувствительные | расписание кабинетов, прайс, ТМЦ, обезличенные агрегаты, витрины | репутационный, минимальный |

## 2. Классификация, обоснование защиты и инструменты

| Данные | Уровень, теги | Состояние | В чём необходимость защиты | Инструменты защиты |
|---|---|---|---|---|
| Медкарта: диагнозы, анамнез, назначения | C4 `pii:special` `medical` | at rest | врачебная тайна (323-ФЗ ст. 13), спец. категория ПДн (152-ФЗ ст. 10); требования приказа ФСТЭК № 21 (УЗ-1/УЗ-2) | шифрование полей на уровне приложения AES-256-GCM (envelope encryption, DEK на запись, KEK в KMS/HashiCorp Vault Transit); TDE PostgreSQL; шифрование дисков (LUKS); ABAC через OPA; аудит каждого чтения в SIEM |
| Медкарта | C4 | in transit | передача между сервисами и на рабочее место врача | TLS 1.3 на внешнем контуре; mTLS между сервисами (Istio/Linkerd); VDI для врачей, запрет экспорта |
| Медкарта | C4 | in use | отображение и обработка | маскирование полей, не нужных роли; break-glass с обоснованием; запрет копирования в буфер/печати в VDI |
| Результаты анализов (PDF, структурированные) | C4 `pii:special` `medical` | at rest | то же; поступают от внешней стороны | S3 с SSE-KMS (ключ на бакет Clinical), object lock/версионирование, retention; метаданные в Clinical DB зашифрованы |
| Результаты анализов | C4 | in transit | обмен с лабораторией через интернет | mTLS с пиннингом сертификата, OAuth2 client credentials, подпись payload (JWS), `lab_pseudonym` вместо Ф. И. О.; запрет e-mail |
| Заключения, выданные пациенту | C4 | in transit | выдача субъекту | только через ЛК/приложение по OIDC-сессии; одноразовые ссылки с TTL; без почты |
| Ф. И. О., дата рождения | C3 `pii:direct` | at rest | прямая идентификация; вместе с C4 - максимальный риск | хранить только в домене Identity; TDE; псевдонимизация (`patient_id`) во всех остальных доменах; HMAC-псевдонимы в аналитике |
| Ф. И. О., ДР | C3 | in transit / use | отображение сотрудникам | маскирование в UI ресепшена и в уведомлениях (И. О.), TLS; выдача по `patient_id` через API с аудитом |
| Паспорт, адрес, договор (сканы) | C3 `pii:direct` `legal` | at rest | 152-ФЗ; договор - юридически значимый документ | S3 SSE-KMS (отдельный ключ), шифрование полей номера паспорта; retention по сроку договора + 5 лет |
| Паспорт, договор | C3 | in transit | загрузка с портала и ресепшена | TLS 1.3, антивирусная проверка вложений, ограничение типов файлов |
| Телефон, e-mail | C2 `pii:contact` | at rest | связывание с C3/C4, спам | TDE; токенизация для рассылок (сервис нотификаций получает токен, не номер) |
| Телефон, e-mail | C2 | in transit | уведомления через внешних провайдеров | TLS к провайдерам SMS/push; содержимое без medical; договор на обработку ПДн с провайдером |
| Платёжные данные (PAN, CVV) | C3 `financial` | all | PCI DSS; не нужны компании | **не хранятся**: hosted page/токенизация у PSP; в Billing только токен и маска `**** 1234` |
| Счета, суммы, статусы | C3 `financial` | at rest / transit | финансовые данные, связка услуга-пациент | TDE Billing DB; TLS к ККМ/ОФД; подпись фискальных документов; в 1С - агрегаты без Ф. И. О. |
| Кадровые данные: ИНН, СНИЛС, паспорт, зарплата | C3 `pii:employee` `hr` | at rest | ПДн работников, 152-ФЗ, ТК РФ | 1С в клиент-серверном режиме, PostgreSQL с TDE; роли 1С; шифрование дисков; журнал регистрации -> SIEM |
| Кадровые данные | C3 | in transit | отчётность в ФНС/СФР | ЭДО с КЭП, TLS; HTTPS-сервисы между базами 1С вместо OLE |
| Учётные данные, токены, ключи | C3 `secret` | all | компрометация = доступ ко всему | Vault для секретов, KMS для ключей, ротация, MFA, короткоживущие токены, HSM/КриптоПро для КЭП |
| Записи на приём (`patient_id`, врач, время) | C2 | at rest / transit | косвенно раскрывает факт обращения к специалисту | TDE; доступ по RBAC/ABAC; в уведомлениях без специализации врача для чувствительных направлений |
| Логи, трассировки, аудит | C2 `audit` | at rest | содержат идентификаторы действий; должны быть неизменяемы | маскирование ПДн до записи; WORM-хранилище (object lock), подпись/хеш-цепочка; retention 1-3 года; доступ только ИБ |
| Резервные копии | наследуют максимум (C4) | at rest / transit | полная копия данных | шифрование бэкапов (ключ отдельно от данных, в KMS); хранение в РФ; TLS при передаче; тест восстановления; retention |
| Озеро данных: `raw` | C4 (копия источников) | at rest | копия всех данных для аналитики | S3 SSE-KMS, закрыта для людей, доступ только ETL-сервисам, короткий retention |
| Озеро данных: `anonymized`, `marts` | C1-C2 | at rest / use | обезличенные данные, риск деанонимизации | псевдонимизация HMAC (ключ в KMS), обобщение дат/адресов, k-анонимность (k >= 5), RLS в ClickHouse, запрет выгрузки сырых строк |
| Рабочие станции и VDI | C4 (в кэше) | in use | локальные копии, скриншоты, USB | BitLocker/LUKS, DLP-агент, запрет USB и локального сохранения, MFA, автоблокировка |
| Почта | C2-C4 | in transit / at rest | исторически основной канал утечки | TLS/MTA-STS, DLP-политики (блок вложений с тегами), запрет пересылки medical, S/MIME для внутреннего документооборота |

## 3. Базовые инструменты защиты

| Класс | Инструмент | Назначение |
|---|---|---|
| Шифрование at rest | PostgreSQL TDE (Postgres Pro / pgcrypto для полей), LUKS на дисках, S3 SSE-KMS, шифрование бэкапов (restic/pgBackRest с ключом из Vault) | защита данных на носителях и в бэкапах |
| Шифрование полей | библиотека envelope encryption в сервисах (AES-256-GCM), KEK в HashiCorp Vault Transit / KMS облака в РФ | защита C4 даже при компрометации БД |
| Управление ключами и секретами | HashiCorp Vault (KMS, PKI для mTLS, секреты), HSM/КриптоПро HSM для КЭП и ГОСТ | ротация, разделение ключей и данных |
| Шифрование in transit | TLS 1.3 на ingress (cert-manager), mTLS между сервисами (Istio), ГОСТ TLS для госорганов (КриптоПро) | защита каналов |
| Аутентификация и авторизация | Keycloak (OIDC, MFA), OPA/Gatekeeper как PEP на шлюзе и в сервисах, RBAC/ABAC по тегам | «запрещено по умолчанию», owner-check |
| Псевдонимизация и обезличивание | HMAC-псевдонимы, библиотека обезличивания в Airflow (ARX / pandas-anonymizer), k-анонимность | аналитика без ПДн |
| Маскирование | маскирование в UI и логах (Vector/Logstash transforms), динамическое маскирование по роли в API | минимум данных в интерфейсе |
| Каталог и теги | OpenMetadata (альтернатива DataHub): теги, lineage, профилирование, автоклассификация | реестр данных, запросы субъектов |
| DLP и endpoint | DLP (например, Solar Dozor / InfoWatch), шифрование дисков, запрет USB, VDI для медперсонала | контроль утечек с рабочих мест |

## 4. Автоматизированный контроль

| Контроль | Средство | Что проверяет |
|---|---|---|
| Privacy Gate в CI/CD | линтер OpenAPI/Avro/миграций (Spectral + кастомные правила), gitleaks, semgrep | тегированные поля не попадают в публичные контракты, логи, внешние топики; секреты не в коде |
| Сканирование хранилищ | профилировщик OpenMetadata, Macie-подобный сканер S3 (regex ПДн) | нетегированные колонки/объекты с ПДн; ПДн вне разрешённых доменов |
| Политики в рантайме | OPA (Gatekeeper в K8s, OPA в шлюзе) | доступ по тегам/ролям/атрибутам; запрет pod без mTLS/без шифрования томов |
| Аудит и аномалии | SIEM (Wazuh / KUMA / MaxPatrol SIEM), UEBA-правила | массовое чтение карт, доступ вне рабочего времени, чтение без записи к врачу, выгрузки |
| Контроль конфигурации | Kyverno/Gatekeeper, Trivy, kube-bench | шифрование томов, образы без уязвимостей, CIS |
| Контроль retention | retention-джобы Airflow + отчёт в каталог | данные старше срока удалены; запрос субъекта выполнен по всем копиям lineage |
| Мониторинг TLS и сертификатов | cert-manager, blackbox-exporter | истечение сертификатов, слабые шифры |
| Тест восстановления бэкапов | плановый restore в изолированной среде | бэкап расшифровывается и восстанавливается |
