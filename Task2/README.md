## Принципы Privacy by Design и как они реализованы

| Принцип | Реализация в архитектуре |
|---|---|
| Proactive, not reactive | риски конфиденциальности закрываются блоками платформы до разработки функций: API Gateway + PEP, каталог тегов, Privacy Gate в CI/CD |
| Privacy as the default | минимальная анкета при регистрации, уведомления без медицинских данных, аналитика только по обезличенным данным, доступ «запрещено по умолчанию» |
| Privacy embedded into design | данные разнесены по доменам с разными тегами и ключами; между доменами - только `patient_id`, а не Ф. И. О. |
| Full functionality | пациент записывается сам и видит свои данные; врач работает с картой; аналитик строит отчёты - ограничения не ломают сценарии |
| End-to-end security | TLS/mTLS, шифрование полей через KMS, аудит каждого обращения к тегированным данным, retention и уничтожение |
| Visibility and transparency | сервис согласий показывает пациенту, что и зачем обрабатывается; lineage в каталоге показывает, где данные |
| Respect for user privacy | отзыв согласия и запрос на удаление выполняются автоматически по lineage |

## Новые блоки в архитектуре

| Блок | Назначение | Риск, который закрывает |
|---|---|---|
| Identity Provider (Keycloak, OIDC, MFA) | единый вход пациентов и сотрудников; роли и атрибуты для RBAC/ABAC; федерация с AD | доменная аутентификация без ролей; пароли в 1С |
| API Gateway + Policy Enforcement Point (OPA) | каждый запрос проверяется по роли, атрибутам субъекта и тегам запрашиваемых данных; rate limit; owner-check для пациентов | один пациент видит данные другого; партнёр получает лишнее |
| Сервис согласий | версии согласий, отзыв, прекращение обработки, сроки хранения по категориям | обработка без согласия, бессрочное хранение |
| Каталог данных и теги (OpenMetadata) | единый словарь тегов, автоклассификация, Data Lineage; выполнение запросов субъектов | неизвестно, где копии; удалить по запросу невозможно |
| KMS + Vault | ключи шифрования полей и дисков, секреты сервисов, ротация | данные в открытом виде на диске и в бэкапах |
| Аудит и мониторинг (SIEM, UEBA) | аудит обращений к тегированным данным, аномалии (массовое чтение, доступ ночью), алерты | утечка не обнаруживается |
| Privacy Gate в CI/CD | линтер OpenAPI/схем БД/топиков: поле с `pii:special` не может попасть в публичный контракт, лог или внешний топик; результат - в мониторинг | новые интеграции приходится перевалидировать вручную |
| Маскирование логов | тегированные поля вырезаются до записи в логи | ПДн в логах и трассировках |
| Политика хранения и уничтожения | retention-джобы по тегам и согласиям; удаление по lineage | бессрочное хранение |
| DLP и защита рабочих мест | запрет USB и локальных копий, VDI для врачей, DLP на почте | копии медкарт на ПК и в почте |

## Домены данных (MVP)

| Домен | Данные и теги | Кто имеет доступ (RBAC/ABAC) |
|---|---|---|
| Identity | контакты, договор - `pii:direct`, `pii:contact`, `legal` | ресепшен (чтение/запись контактов), пациент (свои), врач (только И. О. по `patient_id`) |
| Расписание и уведомления | слоты, записи по `patient_id` | ресепшен (все), врач (свои записи), пациент (свои) |
| Clinical | медкарта, заключения, анализы - `pii:special`, `medical` | врач - ABAC: есть активная запись/назначение к нему; пациент - owner; ресепшен - нет |
| Billing | счета, токены платежей - `financial` | кассир, бухгалтер; пациент - свои счета |
| CRM | обращения, маркетинг - `pii:contact` по согласию, без `medical` | ресепшен, маркетинг |
| Lab Integration | заказы по `lab_pseudonym` | только сервис |

Между доменами данные ходят только через API с `patient_id`; Ф. И. О.
подтягивается из Identity отдельным вызовом, который тоже журналируется.

## Аналитический слой

1. **ETL с обезличиванием (Airflow).** Выгрузка из доменов строится по
   lineage; правила обезличивания выводятся из тегов: `pii:direct` ->
   псевдонимизация (HMAC с ключом в KMS), даты -> обобщение до месяца/года,
   адрес -> район, `pii:special` -> только агрегаты с k-анонимностью (k >= 5).
2. **Озеро данных** - S3 (SSE-KMS) + ClickHouse. Зоны: `raw` (закрыта для
   людей, retention по политике), `anonymized`, `marts`. Row-Level Security
   по филиалу и роли.
3. **BI / ML / LLM** - Superset, Jupyter, ML-платформа работают только с
   `anonymized` и `marts`. Обучение моделей на `raw` запрещено Privacy Gate.
4. Каталог отслеживает lineage до витрины: при отзыве согласия
   псевдонимизированные записи пациента удаляются из `anonymized`, агрегаты
   остаются.

## Этапы

- **MVP (пара месяцев):** IdP, Gateway + PEP, Identity, Расписание,
  Портал клиента и сотрудников, сервис согласий, каталог с тегами, аудит,
  KMS; 1С переводится в клиент-серверный режим; общий диск закрывается для
  медицинских данных.
- **Год:** Clinical, Billing + платёжный шлюз, Lab Integration, CRM,
  мобильное приложение, голосовой робот, аналитический слой, UEBA, Privacy
  Gate в CI/CD, retention-джобы.
